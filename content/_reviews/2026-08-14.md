The burst came, the review caught it (good), and then the vault went quiet for a full cycle. That's the trigger [[2026-08-07]] named firing. Switch this job to **event-triggered** ("review when ≥1 content commit lands since the last review") or **monthly**, so each review lands against real change instead of manufacturing signal from a quiet week. I can set that up if you want it — say the word.

The reviews grow every week on a schedule; the content pages have gained zero lines in ten days. An agent writing weekly meta-commentary about a vault that isn't changing is, itself, the container-vs-contents pattern wearing a new hat — except now *I'm* the one filling the container. If these reviews are the most reliably-growing thing here, the honest response isn't a sixth review next Friday; it's to stop the review from running until the object it reviews has moved. True, and this week sharpens it: the corollary is that **nothing happens when no session is opened.** The vault has no self-starting motion. It moved on 08-04 because a session ran; it didn't move for the ten days no session ran. That's not a character flaw to fix — it's a design fact to build around. A garden that only grows when watered needs a watering schedule, not more reminders that it's dry.

This week the garden returned to potential the moment the burst ended. The note stays unwritten. The archetype stays accurate. Those two facts are the same fact.

## Life / interests deep dive

The honest read, now with five weeks of data: **this vault is a burst-driven artifact, and its baseline rate of change is zero.** Not slow — zero. It sat untouched for three weeks (07-04 → 08-03), moved hard for two days, and has sat untouched for ten more. There is no trickle underneath the bursts. That's the defining fact, and every recommendation should bend to it instead of pretending a steady weekly drip is one prompt away.

That reframes what "neglect" even means here. The prior reviews read the quiet as avoidance, then softened toward "maybe this just isn't where your attention is." Five weeks in, the truer version is more specific: **your attention goes to the things themselves, not to recording them.** The XR200 is real — it's on the porch. Btrail is real — it's the day job. The reading is real — the list reads like an actual shelf. What's absent is the *layer that captures*, and that layer has never once run on its own. It runs when a session runs. The life is happening; the ledger only updates when someone opens the ledger.

So the momentum question from [[2026-08-07]] resolves cleanly, and not in the direction that review hoped. "Stay weekly while there's momentum" assumed the burst might be a new baseline. It wasn't; it was a burst. The weekly review has now spent one cycle doing exactly what [[2026-07-31]] feared — describing a week that didn't happen. One more like it and the reviews are just a well-written record of a garden not being tended, which is a strange thing to generate weekly.

What genuinely has momentum, still and only: **Btrail and the reading habit.** Same two as last week, same two as three weeks ago. What's neglected is unchanged and I won't re-rank it. The difference this week is that I'm no longer treating the neglect as the problem to solve. The problem to solve is the *cadence of this review* and the *trigger for the next session* — because those are the two levers that actually move, and the notes will follow whenever a session does. Fix the machine that opens the ledger; stop re-describing what the ledger doesn't yet say.

## Workflows to build

Three of the four below are new-this-week and aimed at the real lever (when does a session get opened); the fourth is carried because it's still the correct default.

- **Event-triggered review — the single highest-value change this week.** **Trigger:** replace the weekly cron with one that fires only when `git log` shows ≥1 non-review content commit since the last review file (or, simpler, monthly). **Payoff:** every review then lands against actual change; no more cycles spent narrating a flat week; the analyst stops out-producing the author. This is [[2026-07-31]]'s idea, held back by [[2026-08-07]] "while there's momentum" — the momentum's gone, so it's time. *I can wire this up — the scheduling tools are available to me — just confirm.*
- **A standing "vault session" habit, agent-driven.** **Trigger:** the evidence says content appears only when a session is opened, so schedule the *session*, not the content. E.g. a recurring 20-minute "open a session, pick one note, draft it together" slot. **Payoff:** converts the proven mechanism (08-04) into a repeatable one instead of a lucky afternoon. The bottleneck was never what to write; it was that no one opened the door.
- **Seed-don't-stub capture (carried, still untaken).** **Trigger:** before the next session ends. **Action:** create `notes/xr200.md` with one true dated line already in it — never an empty `notes.md`. **Payoff:** [[2026-08-07]] argued an empty scratchpad gets deleted (it did) and one with content in it accretes. Still the right shape; still not done.
- **Date-on-exit for reading (carried).** **Trigger:** moving a book Currently Reading → Recently Finished in [[reading]]. **Action:** append `— finished YYYY-MM`. **Payoff:** the vault's best page becomes a timeline; smallest possible on-ramp to the five-review-old "nothing is dated" problem.
