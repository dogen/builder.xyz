Not re-listing the carried-over ideas (the Pi read-later → `_inbox.md` capture pipeline from [[2026-08-21]], date-on-add reading from [[2026-08-14]] — both still correct, both still untaken). Two, tightened to this week's evidence:

That's `grep -c '^---$'` per file with a threshold of 2 — genuinely ten lines of YAML + shell. **Payoff:** the Interesting bug never ships again, and neither does anything shaped like it. Stop scoping the "nice" version (render preview, `<small>---` detection, `quartz build`); ship the one rule that catches the bug you actually have, then grow it. **Highest-value item, second week running.**
- **A "fix-it" firing, separate from this review.** **Trigger:** a scheduled run notices an open, mechanical, self-contained problem the last review flagged (a broken frontmatter fence, a dead internal link) and it's still unfixed N days later. **Action:** instead of *re-describing* it in a new review, the run proposes the exact one-commit diff (or, if you authorize write access, opens a branch). **Payoff:** closes the gap this whole week exposed — a known, trivial, live bug currently has no route to getting fixed except a human opening a session. The review's job is to *notice*; something should exist whose job is to *close*. This review is read-only by design, which is exactly why the bug is still here.
